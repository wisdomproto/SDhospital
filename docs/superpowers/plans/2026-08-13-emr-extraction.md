# 진료기록 추출 — 진행 상황과 이어받는 법 (2026-08-13)

원장님이 주신 `AI학습용-이민수원장님` 폴더의 진료기록 이미지를 **사람이 직접 읽어**
구조화하고 DB 에 넣는 작업. 채팅이 읽을 「그 아이의 기록」을 만드는 것이 목적이다.

## 지금 어디까지

**갈래가 둘이다** — 의뢰 환자(`_추출`)와 단골(`_추출-단골`).

| | 의뢰 (`D:/sd hospital/AI학습용…`) | 단골 (`D:/sd hospital/일반환자`) |
|---|---|---|
| 추출·적재 | **69 / 106명** | **30 / 42명** (2026-08-18) |
| 남은 것 | 37명 · 1,022장 | 12명 (다음: 문레오 8428 · 44장) |
| 적재 폴더 | `D:/sd hospital/_추출` | `D:/sd hospital/_추출-단골` |

합쳐서 지금 DB 는 **환자 122명 · 회차 있는 아이 94명 · 1,000회차 · 사정 218건(60마리)** 이다.

⚠️ **원본 폴더에는 환자가 241명 있다.** 106명은 그중 **카톡 대화(csv)가 같이 있는 환자**만이다.
채팅을 검증하려면 대화가 있어야 해서 이 집합을 먼저 하기로 했다.
단골 42명도 같은 기준(카톡 있는 아이)이다.

## 이어받는 법

작업 목록은 `D:/sd hospital/_추출/_작업목록.json` 에 있고 `done` 플래그가 갱신돼 있다.
장수 적은 순으로 정렬돼 있으니 위에서부터 하면 된다.

```bash
node scripts/load-emr.mjs "D:/sd hospital/_추출"        # 환자·회차·입원·카톡
node scripts/load-cautions.mjs "D:/sd hospital/_추출"   # _pending ⚠️🚨 → patient_caution
node scripts/load-emr.mjs "D:/sd hospital/_추출-단골" 8428   # 단골은 차트번호 하나만도 됨
```

⚠️ **단골은 `origin: "regular"` 를 넣는다.** 이 한 글자가 컨텍스트에서
「우리가 그 1차 병원이다」 블록을 켠다 — 빠지면 채팅이 **없는 1차 병원으로 보낸다.**
⚠️ **일반환자 폴더에 의뢰 환자가 섞여 있다.** 폴더 위치가 아니라 기록을 보고 정한다
(두부·리봉·루비·장군·빙고·모카·링고·봄이·송이·식구·찌니·왕치즈·김구이는 `referral` 이었다).
⚠️ **폴더 이름의 차트번호를 믿지 않는다** — `5841 땅콩(오동준)` 의 실제 차트는 **7730** 이었고
`import-regulars.mjs` 가 폴더명을 파싱해 5841 로 넣어 뒀다(회차 0건일 때 발견해 고쳤다).

한 명 추출하는 순서:
1. `<원본>/<폴더>/진료기록/*.jpg` 를 **전부 읽는다** (한 명당 8~17장)
2. `D:/sd hospital/_추출/<차트번호>/환자.json` 을 쓴다
3. 위 두 스크립트를 돌린다

`환자.json` 규칙:
- `note` 는 **원문 그대로** 옮긴다 — 진료기록이 표준화돼 있지 않아 요약하면 정보가 사라진다
- 매일 반복되는 청구 항목(입원-일반·수액·정맥카테터·인퓨전펌프·처치-입원·정맥주사)은 **뺀다**
- `deceased: true` + `deceased_note` — 사망이 기록에 **명시된** 경우만
- `_pending` 의 `⚠️` 항목이 곧 `patient_caution` 이 된다

## ⚠️ 이 작업이 실제로 찾아낸 것

숫자를 채우는 일이 아니었다. **채팅이 그대로 열렸으면 사고가 났을 자리**가 나왔다.

⚠️ **`load-cautions.mjs` 가 `🚨` 항목을 전부 조용히 버리고 있었다** (2026-08-17에 고침) —
필터가 `⚠️` 로 시작하는 것만 받았다. **제일 심한 것들이 통째로 안 들어갔다**
