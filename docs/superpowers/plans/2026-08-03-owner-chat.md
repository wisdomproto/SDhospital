# 보호자 채팅 — 실제 상담 105건을 읽고 다시 세운 기획

원장님이 넘겨준 **채널 대화 백업 105건**(`data/[AI학습용] 채널대화백업 (105건).zip`)을 전수 분석했다.
카카오 채널 상담 원본이고, `DATE · USER · MESSAGE` 세 칸이다. USER 가 숫자면 보호자(차트번호), 아니면 병원이다.

⚠️ **원본은 저장소에 넣지 않는다.** 보호자 이름·전화번호가 평문으로 들어 있다(실제로 한 대화에 휴대폰 번호가 그대로 있다).
분석은 임시 폴더에서 하고 여기엔 **집계와 결론만** 남긴다.

## 데이터

| | |
|---|---|
| 대화 | 105건 (환자 1명당 1개 채널) |
| 메시지 | **12,738건** — 보호자 3,463 · 병원 9,275 |
| 기간 | 2023-08-01 ~ 2026-07-30 (약 3년) |
| 대화 길이 | 중앙값 57건 · 최대 667건 |

| 입원이 오간 대화 | 105건 중 **100건** |

## 발견

### 1. 응답 속도는 이미 최고 수준이다. 개선할 여지가 없다

| 사람이 답장하기까지 | |
|---|---|
| 중앙값 | **0분** |
| 10분 안 | **86%** |
| 1시간 안 | 92% |
| 진료시간 밖(19~9시)도 | 중앙값 0분 · 90%가 28분 안 |

자동응답을 걷어내고 **사람이 친 답장만** 센 수치다(자동응답은 병원 메시지의 23%).
**"AI 가 빨리 답해 준다"는 가치가 여기엔 없다.** 24시 병원이라 밤에도 사람이 붙어 있다.

### 2. 대신 그 속도를 사람이 만들고 있다

병원이 친 메시지 **7,104건**(자동 제외). 대화 105개니 **환자 한 명당 68건**이다.
대화가 오간 1,540일 중 **53%는 병원이 먼저 열었다** — 매일 보내는 입원 경과 보고다.
병원 메시지의 23%는 사진·영상이다.

→ **AI 가 노릴 것은 응답 속도가 아니라 이 7,104번의 타이핑이다.**
그중 매일 보내는 경과 보고는 **우리 입원 일일 리포트가 이미 대체하고 있다**.

### 3. 보호자가 묻는 것은 대부분 의학 상담이 아니다

보호자 메시지 3,463건 중 질문형은 1,007건(29%). 주제별로:

| 주제 | 질문 수 | 지금 우리 앱이 답할 수 있나 |
|---|---|---|
| **예약·일정** | **203** | ❌ 예약 기능이 없다 |
| 약·투약 | 110 | △ 처방은 보호자에게 안 보여주는 정책 |
| 검사·결과 | 106 | ✅ 건강검진 화면 |
| 식사·급여 | 105 | ✅ 입원 일일 리포트 |
| 입원 경과·상태 | 95 | ✅ 입원 일일 리포트 |
| 면회 | 75 | ❌ 병원 규칙(FAQ) |
| 수술·마취 | 73 | △ 동의서·회차 리포트 |
| 비용·보험서류 | 55 | ❌ 없음 |
| 퇴원 후 관리 | 50 | △ 리포트의 추가 안내 |
| **순수 증상 상담** | **44 (4.4%)** | — 사람이 해야 한다 |

**의학적 판단을 요구하는 질문은 4.4% 뿐이다.** 나머지는 *기록 조회*와 *일정*이다.

### 4. 가장 큰 덩어리는 재활 환자의 예약 잡기다

일정 관련 메시지 549건. 그중 예약 잡기 317 · 시간 변경 79 · "지금 가도 되나" 69 · "몇 시에 가면 되나" 35.
침치료·수중재활처럼 **주 1~2회 반복 방문**하는 환자가 매번 채팅으로 날짜를 주고받는다.
한 대화가 178일 이어지는 이유가 이것이다.

### 5. 보험 서류 발급이 조용히 반복된다

"진료 내역서 보내주실 수 있을까요? 보험청구 때문에요" 류가 비용 질문 55건의 상당수다.
사람이 PDF 를 찾아 붙여 넣고 있다.

## 설계 결론

### AI 가 하면 안 되는 것

- **의학적 판단·조언.** 질문의 4.4%고, 틀리면 병원이 책임진다.
  우리는 이미 *리포트조차 요약하지 않는다*(진료 원문을 줄여 내보내면 그 문장의 책임을 병원이 진다).
  같은 이유로 **AI 가 보호자에게 직접 의학적 문장을 만들어 보내지 않는다.**
- **처방·진료 원문 노출.** 정책상 보호자에게 안 나가는 것을 채팅이 우회로가 되면 안 된다.
- **"괜찮아요" 류의 안심.** 안심은 근거가 있을 때만 사람이 준다.

### AI 가 할 것 — 3단 구조

```
보호자 질문
   │
   ├─ 1단 · 기록 조회   "우리 아이 오늘 밥 먹었어요?"  → 입원 리포트에서 읽어 그대로 답 + 화면 링크
   │                    "피검사 결과 나왔나요?"        → 검진 발송 여부 확인 후 링크
   │                    확실한 사실만. 없으면 "아직 안 나왔어요"라고 말한다
   │
   ├─ 2단 · 병원 안내   "면회 몇 시예요?" "주차 되나요?" → 사람이 써 둔 FAQ 그대로
   │                    "보험 서류 주세요"              → 발급 요청 접수 → 직원 할 일로
   │
   └─ 3단 · 그 외      의학 질문·판단·예외
                        → **보호자에게 답하지 않는다.** 직원에게 넘기고,
                          직원 화면에 **답장 초안**을 띄운다(과거 상담 7,104건이 재료).
                          보내는 건 사람이 누를 때만.
```

**3단이 이 기획의 핵심이다.** 우리는 이미 같은 구조를 쓰고 있다 —
입원 리포트는 간호사가 채우고(`ready_at`) 수의사가 보낸다(`sent_at`).
채팅도 **AI 가 초안까지, 발송은 사람**으로 둔다. 새 개념을 만들 필요가 없다.

### 순서

| | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **C-1** | **예약** — 재활·재진 반복 방문 예약/변경 | 질문 1위(203건)이고 의학 판단이 0이다. AI 없이도 값이 나온다 |
| **C-2** | **FAQ** — 면회·주차·준비물·금식·비용 안내 (직원이 쓰는 화면 + 조건 매칭) | 답이 고정돼 있다. `case_story` 처럼 태그로 붙인다 |
| **C-3** | **기록 조회 응답** — 밥·배변·검사·퇴원 예정 | 데이터가 이미 있다. 문장만 조립하면 된다(요약이 아니라 조립) |
| **C-4** | **보험 서류 발급 요청** | 반복 노동이고 판단이 없다 |
| **C-5** | **직원용 답장 초안** — 과거 상담을 근거로 제안, 발송은 사람 | 앞의 넷이 걷히고 남는 것이 진짜 상담이다 |

C-1·C-2 만으로 질문의 **약 28%**가 채팅을 안 거치고 끝난다.
C-3 까지면 **50%**를 넘는다. 여기까지 AI 모델이 필요 없다 — 조회와 규칙이다.

## 미해결 / 결정 필요

- **예약이 EMR 밖에 있다.** 지금 병원이 무엇으로 예약을 관리하는지 확인해야 한다.
  우리가 예약 테이블을 새로 만들면 병원의 기존 장부와 두 개가 되고, 그러면 반드시 어긋난다.
- **채팅 채널을 우리가 가져올 것인가.** 지금은 카카오 채널이다. 보호자는 이미 거기 익숙하고,
  앱 안에 채팅을 또 만들면 **두 곳을 다 봐야 하는 사람은 병원**이다. 앱 채팅으로 옮길지, 카카오에 붙일지 정해야 한다.
- **밤에도 사람이 답하는 것을 유지할 것인가.** 지금 강점이지만 사람을 갈아 넣는 구조다.
  줄이려면 무엇을 자동으로 답해도 되는지 원장님과 선을 그어야 한다.
- **과거 상담을 학습 재료로 쓰려면 비식별화가 먼저다.** 이름·전화번호가 평문으로 들어 있다.
